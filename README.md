# Личный бюджет

Учебный проект по информационной безопасности. Локальное приложение для учёта доходов и расходов на Python, Django и SQLite. Интерфейс на русском языке, денежные суммы хранятся в целых копейках.

## Что работает

- Регистрация, вход и выход. Данные пользователей разделены.
- Добавление, изменение и удаление доходов и расходов.
- Свои категории доходов и расходов. Используемую категорию нельзя удалить.
- Общий баланс, доходы и расходы месяца, журнал с фильтрами и постраничным выводом.
- Отчёт по категориям с долями расходов и выгрузка выбранных записей в CSV.
- Месячные лимиты и уведомления о достижении или превышении суммы.
- Резервное копирование и восстановление SQLite.

В первой версии поддерживаются рубли и один баланс на пользователя. Банковских интеграций и синхронизации между компьютерами нет. Начальный остаток можно внести как доход в отдельной категории.

## Быстрый запуск через Docker

Нужны Git, Python 3.12+ для генерации настроек и Docker с Compose. На Windows и macOS можно использовать Docker Desktop. Для первой сборки нужен интернет. Затем приложение работает локально.

```sh
git clone git@github.com:Shibaev-am/MIPT_INFOBEZ.git
cd MIPT_INFOBEZ
python scripts/setup.py
docker compose up --build -d --wait
```

На macOS/Linux вместо `python` может потребоваться `python3`, на Windows — `py`. Если GitHub SSH-ключ на другом компьютере не настроен, клонируйте по HTTPS: `git clone https://github.com/Shibaev-am/MIPT_INFOBEZ.git` (для закрытого репозитория потребуется доступ к аккаунту).

Откройте <http://127.0.0.1:8000> и создайте учётную запись. Заранее заданных паролей нет. Пять базовых категорий появятся автоматически. Сервер привязан к `127.0.0.1` и недоступен из локальной сети.

`scripts/setup.py` создаёт `.env` со случайным индивидуальным ключом и каталоги `data` и `backups`. Существующий `.env` скрипт не перезаписывает. Контейнер при запуске применяет миграции и запускает Gunicorn. Данные хранятся в именованном томе `budget_data`, копии — в `budget_backups`.

```sh
docker compose stop        # остановка
docker compose start       # повторный запуск
docker compose logs --tail 50
```

Обычные `stop`, `start` и `down` сохраняют данные. Команда `docker compose down -v` удаляет тома, в том числе базу и копии; не используйте её для обычной остановки.

Если порт 8000 занят, измените левую часть привязки порта в `compose.yaml`, например на `127.0.0.1:8001:8000`, и откройте порт 8001 в браузере.

## Запуск без Docker

Нужен Python 3.12 или новее.

```sh
python -m venv .venv
```

Активируйте окружение:

```sh
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Далее на всех системах:

```sh
python -m pip install -r requirements.txt
python scripts/setup.py
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py runserver 127.0.0.1:8000 --nostatic
```

Без Docker база расположена в `data/budget.sqlite3`. `runserver` нужен только для локальной разработки; контейнер использует Gunicorn. Статические файлы обслуживаются через WhiteNoise и при выключенном DEBUG. Если поменяли CSS или JavaScript, повторите `collectstatic`.

## Как пользоваться

1. Зарегистрируйтесь. Для пароля требуется не менее 10 символов, распространённые пароли отклоняются.
2. На странице «Обзор» нажмите «Добавить операцию». Выберите тип и категорию, укажите сумму и дату.
3. В «Операциях» можно менять записи и выбирать период, тип или категорию. Фильтры не меняют общий баланс.
4. Создайте собственные категории при необходимости. Чтобы удалить используемую категорию, сначала перенесите её операции и удалите связанные лимиты.
5. В разделе «Лимиты» выберите категорию расходов, месяц и сумму. Лимит достигается при равенстве суммы расходов и бюджета; при превышении отображается разница.
6. В «Отчётах» можно посмотреть структуру расходов и скачать CSV. Разделитель CSV — точка с запятой, кодировка — UTF-8 с BOM.

Пустой фильтр периода означает всё время. При неверных фильтрах выводится ошибка, а выгрузка не выполняется. Отчёт показывает расходы из того же набора записей, что выбран фильтрами.

Для знакомства с приложением можно добавить вымышленные данные в уже зарегистрированную пустую учётную запись:

```sh
docker compose exec web python manage.py seed_demo ВАШ_ЛОГИН
# без Docker:
python manage.py seed_demo ВАШ_ЛОГИН
```

Команда не создаёт пользователей или паролей и откажется менять учётную запись, если в ней уже есть операции или лимиты.

## Резервные копии

Копия содержит данные всех пользователей и хеши паролей. Храните её в закрытом каталоге. Файл `.env` храните отдельно и не публикуйте. Для защиты при поломке диска копируйте резервный файл на другой носитель.

### Docker

Остановите приложение и создайте согласованную копию:

```sh
docker compose stop web
docker compose run --rm --entrypoint python web scripts/database.py backup --file /app/backups/manual.sqlite3
docker compose cp web:/app/backups/manual.sqlite3 backups/manual.sqlite3
docker compose start web
```

Каждый раз выбирайте новое имя, например `manual-2026-10-05.sqlite3`: существующие копии не перезаписываются. `compose cp` выгружает копию из тома на компьютер. Для восстановления из внешнего файла:

```sh
docker compose stop web
docker compose cp backups/manual.sqlite3 web:/app/backups/restore-source.sqlite3
docker compose run --rm --entrypoint python web scripts/database.py restore --file /app/backups/restore-source.sqlite3 --confirm-stopped
docker compose start web
```

До замены базы автоматически создаётся страховочная копия в `budget_backups` с именем `before-restore-...sqlite3`. Её можно также выгрузить через `compose cp`. На Linux скопированный в контейнер файл должен быть доступен пользователю контейнера UID 10001 для чтения; при необходимости используйте `docker compose run --rm --user 0 --entrypoint chown web 10001:10001 /app/backups/restore-source.sqlite3` после копирования.

### Без Docker

Остановите сервер (`Ctrl+C` в его терминале), затем выполните:

```sh
python scripts/database.py backup --file backups/manual.sqlite3
python scripts/database.py restore --file backups/manual.sqlite3 --confirm-stopped
```

После восстановления снова запустите сервер. Восстановление проверяет целостность базы, внешние ключи и наличие таблиц приложения. Текущая база сохраняется перед заменой. Нельзя восстанавливать базу при запущенном приложении. Копии рассчитаны на ту же версию проекта; после обновления кода примените миграции.

## Безопасность

- Пароли хешируются средствами Django с индивидуальной солью.
- Все финансовые запросы ограничены текущим пользователем; переданный из формы `owner` игнорируется.
- Суммы, даты, категории и типы проверяются на сервере. Денежные суммы положительные, максимум одной операции — 9 999 999 999,99 руб.
- Изменения выполняются в транзакциях; в базе есть внешние ключи и ограничения сумм.
- Запросы используют ORM; формы защищены CSRF-токенами; комментарии выводятся с HTML-экранированием.
- Изменения и выход выполняются POST-запросами. Удаление требует отдельного подтверждения.
- В CSV текст, похожий на формулу, получает защитный апостроф.
- DEBUG по умолчанию выключен, секретный ключ не включён в исходный код, контейнер работает без root, access log Gunicorn выключен.

Это локальный учебный проект. HTTP допустим только на loopback. База и копии не зашифрованы: защищайте их правами ОС и шифрованием диска. Пользователь с полным доступом к компьютеру сможет прочитать файлы. Для публикации в интернете дополнительно нужны HTTPS, secure cookies, ограничение попыток входа, настройка хостов и отдельная проверка безопасности. Не открывайте порт наружу с текущими настройками.

## Проверки

```sh
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
# или в контейнере:
docker compose exec web python manage.py test
```

Тесты проверяют регистрацию, расчёт баланса, CRUD, фильтры, отчёты, CSV, лимиты, изоляцию пользователей, CSRF, экранирование, ограничения базы, откат транзакции и восстановление резервной копии. Тестовая база создаётся отдельно; рабочие записи не изменяются.

В GitHub Actions настроены тесты на Windows и Linux с Python 3.12 и отдельная проверка Docker Compose на Linux.

## Структура

- `config/` — настройки, маршруты и WSGI.
- `finance/models.py` — категории, операции и лимиты.
- `finance/forms.py` — формы и проверка ввода.
- `finance/views.py`, `services.py` — обработка запросов и расчёты.
- `templates/`, `static/` — интерфейс без внешних CDN.
- `scripts/` — подготовка настроек и резервное копирование.
- `finance/tests.py` — автоматизированные проверки.

Версии Python-зависимостей зафиксированы в `requirements.txt`. SQLite входит в Python. Образ Docker использует Python 3.12. На компьютере разработчика проверяются отдельная локальная установка и контейнер; результаты CI видны в разделе Actions репозитория.
